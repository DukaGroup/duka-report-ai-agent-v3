# Security review — 22 October 2026

Quick source, dependency and local runtime review. This is not a penetration test or a guarantee that every vulnerability has been found.

## Fixed

- **Saved report access:** report details and all four download formats now recheck current source/database/company permissions, including additional analyses and model-calculation inputs. Registered-script reports also require their current dataset grant. Checks apply to both ChatGPT and Claude. A revoked Manager cannot download an already generated workbook. Deleting an inaccessible report remains possible.
- **CSV formula injection:** column headings now receive the same protection as text values. Leading tab/newline characters are also escaped. Numeric values retain their original types and signs.
- **Private storage:** startup now repairs existing data-directory permissions to `0700`. Previously, `mkdir(mode=...)` only protected newly created directories; the existing local volume was `0755`.
- **Password hashing:** new hashes use OWASP's scrypt configuration `N=16384, r=8, p=5`, replacing the legacy `p=1` cost. Existing passwords remain valid; a successful login upgrades the verifier without changing grants or invalidating existing sessions. See [OWASP password storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html).
- **Dependency updates:** `pypdf` is pinned to `6.21.1`; the container and native deployment instructions install `pip 26.2`. The original Python audit flagged these two packages. The pypdf advisory requires optional Pillow and image loading; this review did not establish an exploitable PDF path. Updating avoids retaining the affected version. See the [maintainer advisory](https://github.com/py-pdf/pypdf/security/advisories/GHSA-5hx5-vpf9-5wcv).

## Remaining actions

**Follow-up:** local remediation is implemented; see [security maintenance](security-maintenance.md). `.env` and `outputs/` are removed from the current Git index and ignored, while their working files remain byte-for-byte intact. Production transport/bootstrap checks and encrypted recovery tools were added, and a filtered history copy was prepared separately. Publishing cleaned remote history and rotating/verifying real database accounts remain operator/DBA actions; they were not performed during local preparation. The first item below records the original finding and its remaining remote-history action.

1. **High: secrets and financial artifacts were present in Git history.** `.env` contains populated password/secret bindings. Financial examples include `outputs/D&D-cutoff-25-08-2026-SAP400.xlsx` and `outputs/report-reference-20261021/visual-inputs.json`. The current index no longer tracks these paths, the local hook blocks re-adding them, and the local working files were verified unchanged. Earlier commits in the original checkout and remote still contain copies. A separate filtered history copy was checked locally; it has not been published. Keep the repository restricted, coordinate any history replacement with other clones, and rotate exposed credentials with the database administrator. Deleting a file in a later commit does not remove earlier copies. See [OWASP secrets management](https://cheatsheetseries.owasp.org/cheatsheets/Secrets_Management_Cheat_Sheet.html).
2. **Before public deployment: HTTPS and secure cookies.** The current local app uses HTTP, localhost origins and `SECURE_COOKIES=false`, with port 8080 bound to loopback. The native deployment guide already requires HTTPS, the exact public `ALLOWED_ORIGINS`, `SECURE_COOKIES=true`, a dedicated service user and a loopback backend. Retain those settings. Complete first-account initialization through a trusted local/SSH connection before making a fresh workspace public: its initial setup endpoint is intentionally unauthenticated until the first account exists. See [OWASP session management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html).
3. **Verify database-side grants and backups on the VPS.** The SQL Server connection's `read_only` option is a routing hint, not a permission boundary. Grant reporting accounts SELECT only on approved business objects; use equivalent HANA permissions. Keep TLS verification enabled where supported. Verify encrypted, restricted backups and a restoration procedure for `.env` and the complete private data directory. This review did not change or inspect live database-account privileges, the VPS, VPN routes or firewall rules.

## Checked and validation

- Reviewed authentication, hashed session storage, password recovery, CSRF/origin checks, role restrictions, owner checks, source/database/company scopes, uploads, calculation/workbook isolation, native provider restrictions, logging redaction and deployment files.
- 245 backend tests passed; two optional native Codex checks were skipped because the native executable was not available to that test environment. Both providers' report tools were exercised with test subscription runtimes, not paid model inference.
- 72 frontend tests passed and the production frontend build completed.
- Frontend and Codex-runtime npm audits reported zero known vulnerabilities. The Python audit with patched versions also reported zero, with no packages skipped. These are advisory-database results, not proof that dependencies are vulnerability-free.
- Unauthenticated conversation/admin endpoints returned `401`. CSP, frame protection and MIME-sniffing protection were present. Requests for `/.env` and `/.git/config` returned the frontend HTML fallback, not file contents.
- No production users, business data or access grants were edited. Current user, source, database, dataset and policy fingerprints match the pre-change baseline; the full real-workspace backup was restored to a separate test directory and verified. Original environment and 153 private tracked working files remain byte-for-byte intact. Audit output and backup fingerprints are private under `work/security-hardening-20261022/` and `work/deployment-backups/security-review-20261022/`.

OS/base-image vulnerability scanning, repository history scanning, adversarial live-model testing, MFA implementation and external penetration testing were outside this quick review.
